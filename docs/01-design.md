## 4. 도메인 규칙 설계

### 4-1. 궁·지지 좌표

- 지지 인덱스: 子=0, 丑=1, 寅=2 … 亥=11. 모델은 **지지 기준**으로 저장한다(iztro의 궁 index 0=寅 이므로 `branch = (idx + 2) % 12`).
- 격자 배치(남쪽 위): 윗줄 巳午未申 / 왼쪽 辰·卯 / 오른쪽 酉·戌 / 아랫줄 寅丑子亥. 가운데 2×2는 정보 블록.
- 삼방사정: 선택 궁의 지지 `b` 기준 `b+4`, `b+8`(삼합), `b+6`(대궁) — R-04.
- 본명 12궁 이름은 명궁에서 시작해 지지 번호가 줄어드는 방향(역행)으로 부여.

### 4-2. 출생 시각 보정 (I-06, I-07, U-06)

사이트는 표를 쓰지만 표를 얻을 수 없으므로 **계산식**으로 대체한다.

```
UTC            = 입력 시각(현지 시계) − 그 시점의 UTC 오프셋(IANA 시간대 데이터, 서머타임·표준시 이력 포함)
평균태양시(LMT) = UTC + 경도/15 시간
진태양시        = LMT + 균시차(그날의 UTC 기준)
```

- 한국의 표준시는 1954-03-21~1961-08-09에 UTC+8:30(동경 127.5°)이었다. 사이트의 “서울 −2분”은 **이 기간에만 맞는** 값으로 추정된다(127.5° 기준). 이번 구현은 시간대 데이터가 이 이력을 가지고 있으므로 따로 처리하지 않는다.
- 보정 방식은 설정으로 고른다: ① 표준시(보정 없음, **기본**·사이트와 같은 기본 동작) ② 경도 보정(평균태양시) ③ 진태양시(경도+균시차). 출생지를 고르지 않으면 ①.
- 보정으로 날짜가 넘어가면(예: 부산 00:20 → 전날 23:56) **날짜도 함께** 넘긴다.
- 균시차는 NOAA 근사식(오차 약 ±30초). 화면에 “보정된 시각”을 항상 보여 준다.
- 호환 모드: 표준시 0분 / 해외 −30분 / 지역 `trunc((경도−127.5)×4)`분. **사이트의 실제 보정표는 입수하지 못해 근사**이며, 품질확인서에 “호환 모드 보정은 근사”로 적는다.
- 출생지 표: 시·군청 소재지 기준 경도 약 160곳 + 해외 주요 도시(시간대 포함) + 경도 직접 입력. 경도 오차 ±0.1° ≈ ±24초.

### 4-3. 시진·자시·윤달 (U-07)

- 시진 인덱스: 0=早子(00:00~00:59), 1=丑 … 11=亥, 12=晚子(23:00~23:59). iztro 규칙과 같다.
- **자시 처리**(설정): `익일 자시`(기본, iztro `dayDivide: forward`, 23시 이후를 다음 날로) / `당일 자시`(`current`).
- **윤달 처리**(설정): `후반 보정`(기본, iztro `fixLeap=true`, 윤달 16일 이후는 다음 달로) / `해당 달 그대로`.
- 시 “모름”(99): 명반을 그리지 않고 N-06 안내(12시진별 명궁·오행국·명궁 주성 비교표)를 보여 준 뒤 시진 선택을 유도한다.

### 4-4. 연도 기준 (R-05, N-03)

- 기본 `음력 설`(iztro `yearDivide: normal`, 사이트와 동일 — 원장 R-05).
- `입춘`(`exact`)을 고르면 연간·연지 기준 별(사화·녹존·천마·오행국 등)이 입춘 시각 기준으로 바뀐다. 실험으로 1990-01-30은 庚午·水二局 → 己巳·金四局로 바뀌는 것을 확인했다.
- iztro 설정은 **전역 상태**이므로 래퍼가 계산 직전마다 설정을 명시적으로 지정하고 직렬로 호출한다.
- 사주 연주는 어느 쪽을 골라도 **항상 입춘 기준**이다(사주의 정의). 탭에서 두 값을 나란히 보여 준다.

### 4-5. 밝기 (F-05, 결정 #2)

| 7단계(원값) | 5단계 표시 | 5단계 지수 | 7단계 지수 |
|---|---|---|---|
| 묘 | ◎ 묘 | 100 | 100 |
| 왕 | ○ 왕 | 75 | 83 |
| 득 | ○ 왕 *(임시)* | 75 | 67 |
| 리 | △ 평 *(임시)* | 50 | 50 |
| 평 | △ 평 | 50 | 33 |
| 불 | / 한 | 25 | 17 |
| 함 | X 함 | 0 | 0 |

득·리의 5단계 대응은 **사이트의 매핑표를 알 수 없어 임시**로 정했다(원장 §8의 “득·리 기호 대응은 임시”와 같은 처지). 7단계 전환 시 원값을 그대로 쓰므로 이 모호함이 사라진다.

### 4-6. 운 모드 (F-08, I-05)

| 모드 | 기준 | 궁 이름 | 추가 표시 |
|---|---|---|---|
| 본명 | — | 본명 12궁 | — |
| 대한 | 선택한 10년 구간 | 대한 명궁이 놓인 칸을 기준으로 재배치 | 대한 사화·운창/운곡 등 운성 |
| 유년 | 기준 연도 | 유년 명궁 기준 | 유년 사화·유성, 세전/장전 12신 |
| 유월 | 기준 월(음력) | 유월 명궁 기준 | 유월 사화·유성 |
| 유일 | 기준 일 | 유일 명궁 기준 | 유일 사화·유성 |
| 유시 | 기준 일시 | 유시 명궁 기준 | 유시 사화·유성 |

- 궁 이름·사화·유성은 iztro의 `horoscope()` 결과(`palaceNames`, `mutagen`, `stars`)를 그대로 쓴다. **유년~유시의 정확도는 U-02로 미확인**이며 엔진 값을 따른다.
- 본명 사화는 채운 배지, 운 사화는 윤곽 배지(`대·록`, `년·기` …)로 구분한다.
- 대한 구간 선택은 `출생 음력년 + 시작나이 − 1`년 7월 1일을 기준일로 환산해 `horoscope()`에 넘긴다(허세 기준, 연중이라 경계 문제 없음).

### 4-7. 지수 (I-11)

- 밝기 평균지수 = 궁의 주성들의 밝기 지수 평균(주성이 없으면 “없음”).
- 길흉 비율지수 = 길성(보좌 8 + 생년 화록·화권·화과) 개수 ÷ (길성 + 흉성(살 6 + 생년 화기) 개수) × 100, 둘 다 0이면 “없음”.
- 이 정의는 원장에 없어 **이 구현의 정의**이며 요약표에 계산 근거를 한 줄로 밝힌다.

### 4-8. 역산 입력 (F-09, I-10, U-04)

사이트의 내부 동작이 미확인(U-04)이라 **입력 → 후보 탐색 → 선택** 방식으로 새로 설계한다.

- 알고 있는 값만 고른다(전부 선택 사항): 연간, 연지, 음력 생월·생일, 시진, 명궁 위치, 신궁 위치, 오행국, 자미성 위치, 좌보·우필·문창·문곡 위치.
- 탐색 공간: 60갑자 연 × 12월 × 30일 × 12시진 = 259,200. 각 조합에서 핵심 위치(명궁, 신궁, 오행국, 자미, 좌보, 우필, 문창, 문곡)를 **독립 구현 공식**으로 계산해 입력과 대조한다.
- 결과: 후보 수, 유일/다수/없음 판정. 없음이면 **어떤 입력 쌍이 함께 성립할 수 없는지**(한 개 제거 시 후보가 생기는 항목, 두 항목 조합의 불가능 여부)를 설명한다.
- 후보를 고르면 해당 간지의 대표 연도(1900~2100 중)를 골라 `byLunar`로 명반을 그린다.
- 호환 모드에서는 검증을 끄고 입력값을 그대로 쓴다(I-10 재현).

## 5. 화면 설계

### 5-1. 레이아웃

| 화면폭 | 구성 |
|---|---|
| ≥ 1180px | 3열: 입력부(좌, 300px) · 명반(중앙, 가변) · 탭 패널(우, 380px) |
| 760~1180px | 입력부는 접히는 상단 카드, 명반 + 탭 패널 2열 |
| < 760px | 상단 탭 3개: **명반 · 궁 해설 · 사주 비교**. 입력부는 명반 탭 맨 위 접이식 |

- 색: 따뜻한 상아색 바탕 + 먹색 글자, 강조는 남색. 록(옥색)·권(황토)·과(청색)·기(주홍). 다크 모드 지원(`prefers-color-scheme`).
- 글꼴: 시스템 한글 글꼴 스택. “글꼴 설정” 팝업에서 크기(3단계)·서체(고딕/명조) 선택.
- 접근성: 모든 조작은 `<button>`/폼 요소, 궁 칸은 키보드 포커스 가능, 색에만 의존하지 않도록 사화는 글자 배지.

### 5-2. 명반 칸 구성 (F-03)

칸 하나 = 간지 · 궁명(+신궁 표지) · 주성(밝기, 사화 배지) · 길성/살성 칩 · 잡성 글자 · 12신 계열(표시 옵션) · 대한 구간 · 소한 나이.
빈 궁(주성 없음)은 대궁 주성을 **흐리게** 보여 주는 옵션을 둔다(차성안궁).

### 5-3. 가운데 정보 블록 (U-01 — 새로 정의)

양력/음력(윤달 표시) · 보정된 시각과 보정량 · 자미두수 연주(기준 표시) · 띠 · 오행국 · 명주/신주 · 명궁/신궁 · 대한 방향(순/역)과 첫 대한 시작나이 · 생년 사화 4개 · **달력 기준 알림**(사주와 연·월이 다르면 한 줄 경고, N-01) · 운 모드일 때 기준 일시.

### 5-4. 우측 패널

**궁 해설 탭**: 요약표(12궁 × 주성·밝기평균·길흉비) → 선택 궁 카드(궁 개요, 주성 없는 궁 안내, 조합 해설, 별 해설 아코디언).
**사주 비교 탭**: 달력 기준 알림 · 연도 기준 선택 · 4기둥 병기표 · 공통점 5 · 차이점 5(각 항목에 **근거 구분 배지**와 **이 명식의 실측값**) · 2단계 자리표시.

### 5-5. 부가 기능 (F-10)

글꼴 설정(팝업) · 이미지 저장(PNG) · 만세력(팝업: 월 달력, 음력·일진·절기 시각) · 음성 읽기(Web Speech, 선택 궁 해설) · 표시 옵션(별 이름 한글/한자 병기, 잡성·12신 표시, 밝기 5/7단계, 빈 궁 차성 표시, 삼방사정 강조).
설정은 `localStorage`에 저장하되 실패해도 동작한다. 입력값은 URL 해시에 담아 공유할 수 있다(서버 전송 없음).

## 6. 해설 새 문안 설계 (N-04, D-02)

### 6-1. 구조 (별 하나의 해설)

1. **한 줄 요약**(20~45자) — 별 키워드 + 이 궁에서의 의미
2. **쉬운 풀이**(주성 90~190자 / 그 외 60~150자) — 별의 성격 + **그 궁의 주제에 맞춘 문장**(14 주성 × 12궁은 직접 작성한 168문장, 나머지는 궁 주제 문장과 합성)
3. **밝기 한 줄**(35~90자) — 5/7단계별 문장 + 주성별 장점·주의 키워드
4. **사화 한 줄**(35~100자) — 이 별에 붙은 록·권·과·기(본명 및 선택한 운 모드의 사화) 영향. 없으면 생략
5. **사주 대응 한 줄**(40~120자) — 이 궁이 사주에서 대응하는 십성/자리와 **이 명식의 실제 값**(예: 재성 개수)

### 6-2. 추가 요소

- **조합 해설**: 같은 궁의 별 조합 규칙 — 녹마교치, 화탐/영탐, 쌍록, 좌우협명 등 동궁·협 규칙과, 삼방사정 격국(살파랑, 기월동량, 양량창록)을 본명 12궁에서 탐지. 이름 붙은 조합이 없으면 두 주성의 성격을 잇는 일반 문장.
- **용어 풀이**: 처음 나오는 전문 용어는 `용어(쉬운 말)` 형태로 풀고, 이후엔 점선 밑줄 + 툴팁.
- **운 모드 어조**: 본명 “타고난”, 대한 “이 10년 동안”, 유년 “올해”, 유월 “이번 달”, 유일 “오늘”, 유시 “이 시각”.
- **차성안궁**: 주성이 없는 궁은 대궁 주성을 빌려 읽는 안내 + “빌린 별은 힘이 덜하다”는 주의.
- **저작권**: 모든 문장을 이 프로젝트에서 새로 작성. 사이트 문장은 열람·복제하지 않았다.
- **어조 원칙**: 단정·공포 조장 표현을 피하고 “~하기 쉽습니다/~에 유의하세요” 형태. 화면 하단에 “전통 이론에 따른 참고용이며 통계로 검증되지 않았다”를 표기.

### 6-3. 길이 균일(I-13)과 궁별 다양성(I-14)을 **자동 검사**한다

- 항목별 글자 수 범위를 코드 상수로 두고, 모든 (별 × 궁 × 밝기 × 사화 × 운 모드) 조합을 생성해 범위를 벗어나는 것이 0건이어야 한다.
- 같은 별의 12궁 풀이가 서로 달라야 하며(중복 0), 사이트의 “44개 중 7개만 궁에 반응”보다 높은 비율이어야 한다.

## 8. 한계와 가정 (설계 시점)

1. **사이트와 직접 비교한 결과를 갖고 있지 않다.** 비교 근거는 원장의 관찰 기록과 독립 엔진뿐이다. 호환 모드의 정확도는 “원장이 기술한 패턴을 얼마나 정확히 옮겼는지”까지만 검증 가능하다.
2. 호환 모드의 출생지 보정·역산·대한 궁 이름은 원장 기술이 모호해 **추정 재현**이다.
3. 해설과 사주 대응은 전통 이론에 근거한 서술이며 통계 검증이 없다.
4. 경도 표는 근사값이며, 해외는 대표 도시만 있다(직접 입력 제공).
5. 사주 엔진은 신규 구성이며 결정 #3에 따라 교체될 수 있다.

### A-2. I-15 *(신규)* 한국 음력 기준 — 검증 중 발견한 결함

- **발견**: 시나리오 검증에서 달력의 근거를 점검하다가, 엔진(iztro·lunar-javascript)의 음력이 **중국 표준시(UTC+8) 날짜**로 세어진다는 점이 한국 음력(한국천문연구원, **한국 표준시 UTC+9** 날짜)과 다를 수 있음을 알았다. 원장은 음력의 기준을 기록하지 않았고(R-01 의 일치 확인은 명반 2건), 설계서도 이 점을 다루지 않았다.
- **크기**: 한국천문연구원 자료 기반 라이브러리와 1900-02-01~2050-12-31 의 55,121일을 대조하니 **1,978일(3.59%, 59개 연도)** 의 음력 날짜가 달랐다. 합삭(초하루를 정하는 순간)이 자정 무렵이면 초하루가 하루 갈리고, 중기가 자정 무렵이면 윤달이 다른 달에 놓인다.
  - 2012년: 한국 윤3월(4/21~5/20) · 중국 윤4월(5/21~6/18) → 연 119일이 다름
  - 2017년: 한국 윤5월 · 중국 윤6월 → 59일
  - 2023-05-19: 중국 음력 4월 1일 · 한국 음력 3월 30일(한국의 석가탄신일 5/27 = 4월 8일)
- **영향**: 음력 일·월은 자미성(일), 좌보·우필·문창·문곡(월·시), 삼태·팔좌(일) 위치를 정하므로 같은 생일시가 다른 명반이 된다(시나리오 K1: 한국 기준 명궁 戌·자미 辰, 중국 기준 명궁 亥·자미 丑). 사주 4기둥은 절기(순간) 기준이라 영향이 없다.
- **대응**
  1. `scripts/lunar-kr-generator.mjs` — 합삭·중기를 천문 계산해 음양력을 만드는 생성기. 규칙: **1912-01-01 이전은 중국 표준시 날짜**(한국천문연구원 표가 이 기간은 중국 음력과 완전히 같다), **이후는 한국 표준시**(1954-03-21~1961-08-09 는 UTC+8:30). 월 번호는 동지가 든 달 = 11월, 13개월 구간의 첫 무중기월 = 윤달.
  2. 결과를 연도별 표로 저장(`src/core/lunarkr-data.ts`, 201개 연도, 2.6KB) — 실행 환경의 부동소수점 차이에 흔들리지 않고 빠르다.
  3. `lunar-lite` 에 달력 공급자(`setLunarProvider`)를 추가해 iztro 가 계산하는 동안만 한국 음력을 쓰게 했다(A-9).
  4. 입력부에 **“음력 기준: 한국(기본) / 중국”** 을 두었다. 바꾸면 바로 다시 계산하고, 두 기준이 다른 날짜에는 중앙 블록·사주 비교 알림에 다른 기준의 음력 날짜를 보여 준다. 공유 링크(`lb=cn`)·만세력·역산 입력이 같은 기준을 쓴다. **호환 모드는 항상 중국 기준**(사이트가 iztro 계열과 같다고 추정).
- **검증**(`tests/lunarkr.test.ts` 21건): ① 한국천문연구원 자료 기반 라이브러리와 55,121일 **0건 불일치**(양력→음력, 음력→양력 전수, 윤달 해·번호) ② 생성기를 처음부터 다시 돌려 저장한 표와 동일 ③ 생성기를 중국 표준시로 돌리면 lunar-javascript 와 1961~2099 의 50,769일 동일(알고리즘 검증) ④ 달 길이·윤달·정월 범위·1900-01-31~2101-01-28 왕복 변환 ⑤ 사람이 아는 사실(석가탄신일 2012~2026, 설날·추석 2015~2026, 2012·2017 윤달) ⑥ 패치 경로 중립성(중국 공급자를 끼워도 300건 명반 동일) ⑦ 달라지는 날 300건은 독립 구현과 일치. **변이 검사**: 공급자를 끄면 7건이 실패한다.
- **사용자 확인이 필요한 결정**: 기본값을 한국으로 정했다(한국 만세력과 일치). 원본 사이트가 중국 기준이라면 3.6%의 날짜에서 사이트와 명반이 달라지므로, 사이트와 완전히 같게 쓰려면 “중국”을 고르거나 호환 모드를 쓴다 — 05-feedback.md 의 결정 1.
- **한계**: 한국천문연구원 원자료를 직접 열람하지 못했고, 그 자료에서 만들어진 공개 라이브러리(`korean-lunar-calendar`, 범위 ~2050-12-31)로 대조했다. 2051~2100년은 같은 규칙의 계산값이다.

### A-3. 입춘 기준 연주는 출생 순간으로 판정 (설계 4-4 보완)

엔진(iztro → lunar-lite)은 “입춘 기준” 연주를 **날짜 단위**로만 판정해 입춘 당일에는 절입 시각 전에 태어나도 새해로 본다(탐침: 입춘 당일 276건 중 158건이 사주 연주와 불일치). 한국과 중국의 날짜 차이로 전후 하루도 어긋날 수 있다. `src/core/solarterms.ts: ipchunYearOf` 가 출생 **순간**을 UTC+8 절기표의 입춘 시각과 분·초 단위로 비교하고, 그 연주를 `lunar-lite` 패치(`setBirthYearOverride`)로 그 날짜에 한해 엔진에 넘긴다.
검증: 절입 ±25시간의 아홉 지점 × 25개 연도(225건)에서 명반 연주 = 사주 연주, 임의 시각 3,000건에서 `ipchunYearOf` = lunar-javascript 정밀 연주. **패치를 끄면 8건 중 4건이 실패**한다(225건 중 93건 불일치). 한계: 유년·유월 등 운의 경계는 날짜 단위 그대로다(U-02).

### A-4. 출생지 시각 보정의 기본 모드 (설계 4-2와 다른 점)

설계서는 보정 방식의 기본을 “① 표준시(보정 없음)”로 했으나, 출생지를 골랐는데 아무 일도 일어나지 않으면 F-02 의 의미가 없다. 그래서 **출생지를 고르지 않으면 보정하지 않고(표준시), 출생지를 고르면 진태양시(경도 + 균시차)로 보정**한다. 고급 설정에서 평균태양시·보정 안 함으로 바꿀 수 있다. 첫 화면 예시(T6)는 출생지가 표준시라 영향이 없다.

### A-5. N-08 *(신규, 설계 중 추가)* 자시(23시대) 이월

엔진에는 항상 시진 0~11(早子~亥)만 넘기고, 23시대(晚子)의 날짜 이월은 `time.ts` 가 처리한다 — 익일 자시(기본)이면 날짜를 하루 넘기고 시진은 子, 당일 자시(야자시)이면 날짜를 두고 시진은 子. 사주 일주도 같은 설정(`sect`)을 따른다. 연말·음력 설 전날·범위 끝(2100-12-31) 경계는 `tests/scenarios.test.ts` 가 확인한다.

### A-6. 역산 입력 (설계 4-8 보완)

- 입력 항목에 **삼태·팔좌 위치**를 더했다(월·일에 따라 정해지는 별).
- 같은 달의 d일과 d+24일은 명반이 같아 구분할 수 없음을 결과 아래에 안내한다(`tests/engine.test.ts` 가 사실을 확인). 연지를 모르면 6가지 해가 모두 후보로 나온다.
- 후보의 대표 연도 목록은 음력 기준(A-2)을 따른다(예: 30일이 있는 해가 한국·중국에서 다르다).

### A-7. 공유 링크는 해시(#) 사용 (설계 5-5와 같은 약속을 지키기 위한 수정)

설계서는 “입력값은 URL 해시에 담아 공유(서버 전송 없음)”였으나 처음 구현은 쿼리(`?y=…`)였다. 쿼리는 정적 서버의 접근 기록에 남으므로 화면 문구(“어디로도 전송되지 않습니다”)와 맞지 않았다. 지금은 `#y=…&m=…` 이며, 예전 쿼리 링크는 읽기만 한다. 검증용 스위치 `?compat=1` 만 쿼리에 둔다(개인정보가 아님). E2E 가 서버가 실제로 받은 요청 주소에 생년월일시가 없음을 확인한다(감시 장치의 민감도도 함께 확인).

### A-8. 배포 형태

`dist/` 는 **정적 서버 없이 `index.html` 을 더블클릭해도 열린다**(file://). 빌드를 IIFE 한 파일로 묶고 `type="module"`·`crossorigin` 을 떼었으며(브라우저가 file:// 에서 막는 속성), 코드 분할을 쓰지 않는다. `base: './'` 라 GitHub Pages 의 하위 경로(`/저장소/`)도 된다(E2E 확인).

### A-9. 의존성 패치와 개발 전용 의존성

`lunar-lite@0.2.8` 의 파일 5개를 설치 직후 덮어쓴다(`scripts/apply-patches.mjs`, `patches/`). 처음에는 patch-package 를 썼으나 그 하위 의존성(braces)에 수정본이 없는 고위험 경고 4건이 떠서(개발 전용이지만 회사 보안 점검에 걸릴 수 있음) **의존성 없는 해시 검증 덮어쓰기**로 바꿨다. 설치된 파일의 해시가 원본도 패치본도 아니면 **아무것도 쓰지 않고 설치를 멈춘다**(원자적). `npm audit` 0건(개발 의존성 포함).

### A-10. 화면·동작의 변경

### B-4. 설계

**화면 순서(궁 해설 탭)** — ① 해설 읽는 법(접힘) ② 12궁 요약표 ③ 선택한 칸: 이름 → 이 칸은(개요) → 운 모드 안내 → **한눈에 보기** → 함께 읽는 칸 → (빈 궁이면) 빌려 읽기 안내 → 조합 해설 → 이 칸에 흐르는 운 → 별 해설 → **사주로 보면**.

**한눈에 보기 구성** (`compose.ts: buildGlance`, 모두 일상어 짧은 문장)

1. **결론**: “{시기} {칸 주제}에서는 {중심 별의 강점}이 강점이고, {주의점}은 조심할 점입니다.” + 별의 힘(밝기) 한 마디 + 주성이 둘이면 둘째 별의 성격 한 마디. 주성이 없으면 “중심 별이 없어 맞은편 {칸}의 {별}을 빌려 읽습니다”로 시작.
2. **항목**: 중심 별(별 × 궁 문장, 주성 최대 3) · 별의 힘(별마다 한 줄) · 생년·운 사화(별마다 한 줄) · **함께 있는 별**(역할별 한 줄: 도움이 되는 별 → 분위기를 더하는 별 → 신경 쓸 별).
3. 보좌·살성·잡성의 “이 칸에서의 영향”은 별마다 붙이지 않고 **역할 × 궁 문장 13 × 12 = 156개**(직접 작성)를 역할당 한 번만 보여 준다 — 별 카드의 상투적 꼬리 문장을 없애고 중복을 막는다.

**별 카드** — 주성: 요약 · 풀이(뜻 + 별 × 궁 문장) · (본명 기준) · 밝기 · 사화 · 사주 대응. 그 밖: 요약 · 풀이(별 뜻) · 밝기 · 사화 · 사주 대응.

**문안 규칙**: ① 한 문장에 한 가지 뜻, 60자 이하 ② 전문용어보다 일상어, 쓰면 {{ }} ③ 추상 명사 나열보다 장면 ④ 장점·단점은 문장을 나눈다 ⑤ “~할 수 있습니다/~하기 쉽습니다” 등 단정하지 않는 어조 유지 ⑥ ‘명식’ 대신 ‘사주’, ‘지지’·‘충’ 같은 말은 풀어서.

**밝기 문장**: “이 별의 {{밝기}}는 ‘함’으로, 힘이 가장 약한 자리입니다. 그래서 …” — 첫 문장이 기호의 뜻을 말하고 둘째 문장이 결과를 말한다. **사화 문장**: “생년 {{화록}}이 이 별에 붙어 있습니다.” + 결과 한두 문장.

**사주 대응 문장**: ① 사주에서 이 칸을 어떻게 보는지(쉬운 말) ② 이 사주의 값(개수는 없음·적은 편·보통·많은 편 표현 병기) ③ 그 뜻 한 줄(“~로 봅니다”). 건강은 오행별 몸 부위, 이동은 역마 유무, 명궁은 일간의 물상(을=풀·덩굴 등)을 쓴다. 판단의 깊이는 범주의 일반 의미까지로 제한한다(재물·직업·배우자 등을 사주·자미두수가 어떻게 엇갈리는지 비교하는 **교차 보기 2단계(N-05)는 여전히 승인 대기**).

**사주 비교 탭**: 본문·실측 문장을 용어 표시로 렌더, 항목마다 근거 목록을 “근거 보기”로 접는다(내부 번호는 접힌 안에만).

**글로서리 보강**: 연간·연지·월지·일지·월주·연주·시주·건록·충·신살·도화살·오행·사주·간지·천간·지지·귀인(풀이는 일상어 한 줄, 괄호에 넣어도 어색하지 않게).

### B-6. 구현 결과 — 설계(B-3·B-4)에서 바뀐 점과 이유

설계대로 구현한 것은 한눈에 보기의 구성(결론 + 항목), 역할 × 궁 문장 156개, 밝기·사화 문장의 2단 구조, 사주 대응 3단 구조(무엇을 보는지 → 이 사주의 값 → 뜻), 근거 접기, 글로서리 보강이다. 아래는 **검증·독자 시험을 거치며 설계와 달라진 부분**이다.

| # | 설계 | 실제 구현 | 바꾼 이유 (발견 수단) |
|---|---|---|---|
| 1 | 결론: “{주제}에서는 {중심 별의 강점}이 강점이고, {주의점}은 조심할 점입니다.” | “{주제}에서 중심이 되는 별은 {별}입니다. {별}은 {강점}이 강점이고, {주의점}은 조심할 점입니다.” (주성이 둘이면 “여기에 {둘째 별}의 성격({별의 한 줄 성격})이 더해집니다.”, 주성이 없으면 빌려 오는 안내로 시작) | 생성 문장을 직접 읽다가 “몸의 컨디션과 건강 습관에서는 공정함과 베푸는 힘이 강점입니다”처럼 **칸 주제의 강점**으로 읽히는 오해를 찾았다. 강점·주의점의 주어를 별로 고정했다 |

**하지 않은 것(범위 밖, 승인 대기)**: ① **교차 보기(N-05)** — 재물·직업·배우자 등을 두 체계가 어떻게 같고 다르게 말하는지 비교하는 해석은 만들지 않았다. 사주 쪽 문장은 범주의 일반 의미(개수의 뜻)까지만 말한다. ② 해설의 명리적 타당성에 대한 전문가 감수. ③ 실제 사람 독자 시험(V-22 는 AI 독자).

### C-4. 알려진 차이·주의

- **기본 결과가 사이트와 달라진다**: 같은 시계 시각이라도 :00~:29 구간은 이전 시진으로 계산된다. 사이트와 같은 값을 보려면 “시계 시각 그대로(보정 안 함)” 또는 `?compat=1`.
- **이전에 만든 링크**(p 없음)는 이제 한국식으로 읽힌다. 시계 시각이 시진 경계 부근이면 결과가 달라질 수 있다.
- “시 모름” 표와 역산 후보는 시진의 한가운데 시각(예: 12:30)을 채워 경계에 걸리지 않게 한다.
- 균시차는 포함하지 않는다(한국식은 경도 기준만). 필요하면 기존 “출생지 보정(진태양시)”을 쓴다.

## 부록 D. 종합 통변 · 사주 통변 · 통변 비교 (사용자 결정 반영, 2026-10-09)

### D-1. 사용자 결정

> “자미두수 통변을 저렇게 하면 어떻게 하냐 — **종합적 해석**이 들어가야지. 그리고 사주와 비교하랬더니 **이론적 비교**를 하면 어떻게 하냐. **자미두수 통변내용과 사주명리학적 통변을 비교**해줘야지.”

이 지시는 원장의 **N-05(교차 보기 2단계, 승인 대기)를 승인**한 것으로 받아들인다. 설계서 1-1의 결정 #1(“1단계만”)은 이 부록으로 대체되고, 결정 #3(사주 엔진)은 “**새로 구성한 규칙 기반 간이 통변**”으로 확정한다(`SajuEngine` 인터페이스는 계산용으로 그대로, 해석은 `core/tongbyeon/`).

**5-5. 대한(10년) 점수**: 같은 계산을 **그 대한의 궁 이름표**로 다시 한다(대한 명궁을 기준으로 12궁 이름이 옮겨 감). 여기에 대한 사화(록 +0.48·권 +0.32·과 +0.28·기 −0.56, 즉 생년 값의 80%)와 대한 유성(운록 +0.35 · 운양 −0.40 · 운타 −0.35 · 운창·운곡·운괴·운월 +0.2)을 그 칸에 더한다. 대한의 종합 경향은 6개 영역 점수의 평균이다.

**5-6. 경향 단계**: 점수를 **무작위 명반 6,000개**의 분포에서 10·35·65·90 백분위로 나눈다(영역마다 따로, 본명과 대한 따로). 즉 −2는 하위 10%, +2는 상위 10%에 해당하는 **상대 위치**다. 경계값은 `calibration.ts`에 기록하고, 재생성 방법과 분포 시험을 둔다.

**5-7. 주제(Theme) 판정**: 주성 14개 × 영역별 주제 표(예: 재물 — 무곡·천부 → 꾸준히 모음/지킴, 탐랑 → 기회, 파군·칠살 → 기복/지출, 거문 → 노력으로 번 돈), 보좌성·살성·사화·협이 주제를 더하거나 바꾼다. 영역당 최대 3개를 점수순으로 고른다.

### D-6. 사주 통변 규칙

**6-1. 기운 분포 E(그룹)** — 일간을 뺀 7자리(시 모름이면 5자리)의 십성 그룹(비겁·식상·재성·관성·인성) 비중. 자리 가중치: 월지 3 · 일지 2 · 시지 1.5 · 연지 1 · 월간 1.5 · 시간 1.5 · 연간 1. 지지는 지장간을 본기·중기·여기 비중(1개: 1 / 2개: 0.7·0.3 / 3개: 0.6·0.3·0.1)으로 나눈다. 합계가 1이 되게 정규화한다.

**6-2. 강약** — 도움 지수 H = E(비겁) + E(인성). 무작위 사주 분포의 35·65 백분위로 **신약 / 중화 / 신강**을 나눈다. 월지에서 일간이 장생·관대·건록·제왕이면 **득령**을 표시한다. 한쪽으로 극단(분포 상·하위 3%)이면 “치우침이 커서 종격 여부를 전문가가 확인해야 함”을 덧붙인다.

**6-3. 격국** — 월지의 지장간 중 천간(연·월·시)에 드러난 것(투출)을 본기→중기→여기 순으로 고르고, 없으면 본기. 그 십성으로 식신격·상관격·편재격·정재격·편관격·정관격·편인격·정인격을 정한다. 월지가 일간의 건록이면 **건록격**, 양간의 제왕이면 **양인격**. 성격/패격은 간이 조건으로 표시한다(예: 정관격 — 상관이 있어 관을 해치면 패격 표시, 재성·인성이 받쳐 주면 성격 표시).

**6-4. 용신(간이)** — ① 조후가 극단이면(겨울 월지에 수 3개 이상 → 화 / 여름 월지에 화 3개 이상 → 수) 조후 우선, ② 아니면 강약으로: 신강 → 도움 그룹이 인성 위주면 재성, 비겁 위주면 식상·관성·재성 중 가장 약한 것 / 신약 → 재성이 가장 크면 비겁, 아니면 인성 / 중화 → 가장 적은 오행. 희신 = 용신을 생하는 오행, 기신 = 용신을 극하는 오행, 구신 = 기신을 생하는 오행, 나머지는 한신. **“정통 사주에서도 전문가마다 용신이 달라진다”** 를 화면에 적는다.

**6-5. 십성 구조 규칙(S-ST)**: 식상생재 · 재생관 · 관인상생 · 식신제살 · 상관견관 · 상관패인 · 군겁쟁재 · 재다신약 · 관살혼잡 · 인성 과다 · 비겁 과다 · 식상 과다 · 편인도식 · 무재 · 무관 · 무인.

**6-6. 합충**: 천간합(갑기·을경·병신·정임·무계) · 천간충(갑경·을신·병임·정계) · 육합 · 삼합(3자) · 반합(왕지 포함 2자) · 방합 · 충. 어느 기둥(연·월·일·시)끼리인지를 함께 쓴다(일지 충 → 배우자 자리의 흔들림, 월지 충 → 직장·환경의 변동 등 기둥의 전통 뜻). 형·해·파는 이번 범위에서 제외한다.

**6-7. 영역 점수(규칙 합산)** — 영역마다 아래 규칙의 합이며, 단계는 5-6과 같이 분포의 백분위로 나눈다.

### D-7. 비교 규칙

| 판정 | 조건(경향 l_자미, l_사주) | 뜻 |
|---|---|---|
| **일치** | 같은 단계이거나 같은 부호(둘 다 + 또는 둘 다 −) | 같은 방향. 주제가 겹치면 “같은 이유”, 겹치지 않으면 “같은 결론, 다른 이유” |
| **보완** | 한쪽이 0(무난)이고 다른 쪽이 ±1 이상 | 한쪽은 뚜렷하게, 다른 쪽은 무난하게 봄. 뚜렷한 쪽의 근거를 참고 |
| **엇갈림** | 부호가 반대(+와 −) | 두 체계가 반대로 봄. **어느 쪽이 맞다고 판정하지 않고**, 각자의 렌즈(예: 자미두수 = 그 자리의 별 구조 / 사주 = 오행 균형과 받아 낼 힘)가 다른 데서 오는 차이로 설명 |

- 이유 문장은 영역별 **렌즈 표**(각 체계가 그 영역을 무엇으로 보는지)와 각 통변의 **상위 근거 1~2개**를 조립한다.
- 요약: “6영역 중 일치 n · 보완 n · 엇갈림 n”, 가장 크게 같은 말을 하는 영역 / 가장 크게 엇갈리는 영역.
- **시기 비교**: 자미두수 대한 [시작 연도, 끝 연도] = [기준연도 + 시작 나이 − 1, 기준연도 + 끝 나이 − 1], 사주 대운 [시작 연도, +9]. 대한마다 연도가 가장 많이 겹치는 대운을 짝지어(동률은 앞 대운) 같은 판정 규칙을 적용한다. 겹침이 3년 미만이면 “짝 없음”.

### D-10. 한계와 가정 (설계 시점)

1. **규칙 기반 간이 통변**이다. 전통 이론의 일부를 규칙으로 옮긴 것이며, 실제 상담가가 보는 모든 요소(궁간 비화, 유년·유월, 사주의 형·해·파, 종격·화격, 지지 지장간 사령 등)를 담지 않는다.
2. 점수표의 수치는 **설계자가 정한 값**이다. 전통 문헌의 정량값이 아니며 통계로 검증하지 않았다. 단계는 무작위 명반 분포의 백분위로 나눈 **상대 위치**다.
3. **전문가 감수를 받지 않았다.** 감수 결과에 따라 규칙·문구가 바뀔 수 있다.
4. 두 체계가 엇갈릴 때 **어느 쪽이 맞는지 이 사이트는 판정하지 않는다.**
5. 건강·재물·관계에 대한 문장은 **생활 점검의 참고**이며 진단·투자·법률 조언이 아니다.

**측정으로 확인한 사실** (검증 보고서 V-24~V-32 에 근거)

- 새 표본에서 경향 단계 비율은 목표 ±7%p 안에 든다. 보정 표본에서 최대 어긋남은 자미두수 영역 0.6%p · 대한 영역 0.5%p · 대한 종합 2.3%p · 사주 영역 3.4%p · 사주 대운 5.2%p. 경계값은 같은 시드로 다시 만들면 **글자 하나까지 같다**(검증 중 확인). 화면에 나오는 구간(새 무작위 출생 600건): 자미두수 대한 10구간 6,000개의 종합 단계 8.1 / 27.6 / 30.4 / 22.9 / 11.0%(최대 2.6%p), 사주 대운 8구간 4,800개 11.2 / 28.2 / 34.2 / 21.8 / 4.6%(최대 5.4%p) — 경계값을 12구간으로 만들었는데 화면은 10구간만 보여 대한 종합 단계는 보정 표본보다 조금 더 어긋난다. 같은 사람의 구간끼리 뚜렷이 다를 때만 붙는 “가장 나은 때 · 가장 신경 쓸 때” 표시는 자미두수 600명 중 551명(92%), 사주 600명 중 600명에게 붙고 나머지 49명(8%)은 “차이가 작다”는 안내가 나온다.
- 통변 문장은 모두 60자 이하(최대 55자, 평균 25.3자). 무작위 명반 300개의 53,330개 덩어리(문장 169,046개)에서 전문용어 표시 누락·되풀이·괄호 중첩·단정 어조·“열두 구간” 표현이 0건.
- 명반 1개의 계산(명반 + 사주 + 통변 + 비교 + 대한 10구간)은 평균 140~275ms(실행마다 다름, 로컬 컨테이너, 시험의 한계는 1초).
- 두 체계의 영역 판정은 **우연 수준으로만 일치**한다(위 8번). 이 간이 규칙으로는 “두 방법이 같은 말을 했으니 믿을 만하다”고 말할 수 없다. 비교는 읽을거리와 점검 목록이지 교차 검증이 아니다. 시기 비교(새 출생 600건 × 10구간 = 6,000쌍)는 일치 28.3% · 보완 36.8% · 엇갈림 19.2% · 짝 없음 15.7%(자미두수는 100세까지 10구간, 사주는 8구간이라 뒤쪽 대한은 짝이 없다).
